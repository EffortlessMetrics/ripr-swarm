## Audit (REVIEW MEANS)

Three reviewers worked independently from raw Git against the rule-v1 head
`4f7ca02de`, each from a different angle, over a 105-row sample (every
disposition x path-class cell up to 10 rows plus every overridden row) or the
full range.

1. **Dispositions (105 rows).** 0 disagreements with the rule on disposition,
   theme or claim ref. Rule problems found, by rows affected:
   - Path-only classification cannot see in-file test code: up to 53
     `test(...)` commits that only edit `#[cfg(test)]` modules inside
     `crates/ripr/src` are labelled product. **Not fixed**; recorded as a
     limitation below.
   - Product prefixes caught non-product files: `editors/` lockfiles, `.md`
     files and test directories (about 21 commits). **Fixed**: any `.md` is
     docs, `package-lock.json` is control, and `test/`, `testing/` and
     `test-fixtures/` paths are evidence. Product fell from 1,521 to 1,508
     rows.
   - Control mixes unshipped automation (`xtask`) with release-affecting
     packaging. **Not fixed**; limitation.
   - The five empty-diff overrides used a different principle than the other
     overrides. **Fixed**: they now take what the effect steps give a commit
     with no blob effect, `included_historical_reachable_only`.
   - `schemas/` as product is sound for this range (3 rows depend on it).
2. **Tree effect (all 2,213 rows).** 0 mismatches against a full blame pass
   over every alive touched path (11,538 paths, versus capture's 1,726), all
   43 non-effective rows rechecked three ways, and all 2,170 effective rows
   confirmed. No commit loses effect through capture's blame-selection
   shortcut in this range (an empirical result, not a proof). Five effective
   rows are borderline (a merge effective only through last-toucher paths, three
   whose surviving lines are blank or a brace); a stricter ownership definition
   would flip up to 5 rows. One row depends on blame flavor (`051ffb0c8b`:
   plain blame gives it nothing, `-w -M -C -C` gives 5 lines); the rule uses plain
   blame.
3. **Range, identity and digests (full ledger).** 0 discrepancies: range,
   reachable order, parents, trees, subjects, PR extraction and all four
   digests reproduced independently, byte for byte. The packet digest and claim
   rows match. All five corruptions (drop a record, swap first-parent entries,
   change a reachable SHA with counts intact, free-form disposition, zeroed
   digest) were rejected. 37 first-parent commits have no trailing `(#N)`;
   two of them are `Merge pull request #N` subjects whose number is recorded as
   a mention, not a merged PR.

The validator also now refuses a final ledger validated without the packet

## Limitations carried by this ledger

- Dispositions are derived from paths and tree effect only. Product means a
  path under `crates/ripr/src`, `editors/` or `schemas/` changed, including
  commits whose only change is inline test or doc-comment text (up to about 83
  rows, an unchecked upper bound).
- `release_or_control` does not separate `xtask` from release-affecting
  packaging; a mixed commit carries one theme.
- `included_with_release_nonclaim` marks a subject naming a deferred claim's
  owner issue, including the commit that implements a fix.
- `source_sync_authority_effect` is `not_established` on every row: the
  source-parent path inventory is not an input.
- The validator checks the ledger against itself and the packet, not against
  Git; Git agreement here comes from the independent audit and from `capture`.
- The refined rule (the path-class fixes above) was checked by unit tests and
  the re-derived counts, not re-audited row by row.
