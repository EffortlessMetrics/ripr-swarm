# ripr 0.11.0

ripr 0.11.0 checks the behavior changed in a diff and reports where your tests run that code but may not check its result. It still finds this statically, without running mutants. In this release, ripr is stricter about when a test counts as checking a change, and it names a limitation when it cannot decide. It adds a read-only MCP server and a targeted rerun command. The VS Code extension now verifies the server it downloads before using it. It replaces the staged 0.10.1, which was never published. See the [Terminology bridge](https://github.com/EffortlessMetrics/ripr/blob/main/docs/TERMINOLOGY.md) for the terms used below.

## Command line and first use

- `git diff origin/main | ripr check --diff -` reads the diff from stdin. A diff with no file changes now says so instead of quietly reporting zero findings. <!-- swarm #2655, #2425 -->
- A mistyped flag suggests the closest flag the command's own `--help` lists, across the public commands, including `explain`, `context`, `cache`, and `first-pr`. <!-- swarm #2583, #3812, #3786, unnumbered explain/context entry -->
- `ripr init --dry-run` fails wherever the real run would fail, and prints the planned action for each file first. <!-- swarm #2576 -->
- Default `check` output names the `ripr explain` and `ripr context` commands to run next, keeping the original root and diff scope. It no longer prints a `Hidden:` heading when nothing was hidden. <!-- swarm #2598, #2659, #2571 -->
- `ripr doctor` says whether the start-here packet exists yet. The `ripr first-pr --check` recovery command now writes to the same directory that `--check` looks in. <!-- swarm-missing #3866, #3869/#3873 -->
- New advisory commands: `ripr rerun` re-analyzes only the gaps whose tests changed. `ripr plus`, `pr-summary`, `pr-evidence`, `annotations`, and `impacted-evidence` produce repository and PR reports. `ripr cache status` and `ripr cache clear` manage the analysis cache. None of these is a merge gate. <!-- swarm #1520, #1476/#1460/#1468/#1467/#1474, #1822/#2865/#2738 -->
- `check --suppression-policy` and `gate evaluate --exception-policy` read committed policy files. Suppressed findings stay visible as suppressed. <!-- swarm #1475, #1477 -->
- Unchanged files reuse cached analysis, and follow-up commands reuse the previous run's results. <!-- swarm #2039, #2322, #2250 -->

## Analysis accuracy

- A test only counts as checking a change when that single test is tied to the changed code (it calls it, targets it, or is named for it) and asserts its result. A test that just sits in the same file or shares a word with the code no longer counts. Some findings that read `exposed` in 0.10 now read `weakly_exposed`, and the finding says why. <!-- source-missing #1747, #1751 -->
- Literal Rust `match` arms are credited only when a test calls the code with the input that selects that arm. A test that checks a different arm, or text inside a comment, no longer counts. One narrow shape can now be credited: a `match` over two `bool` parameters where a test asserts the exact input and result. <!-- swarm-missing #3759, #3766, #3767; source #1716, #1723 -->
- When ripr cannot work out a boundary's operand values, or cannot follow a guarded error return, it reports a named limitation instead of telling you to add a test that may already exist. <!-- source-missing #1724, #1726 -->
- Fewer spurious findings: changed parameter and struct-field declarations are reported as `static_unknown`, and the closing brace of an added `#[cfg(test)]` module no longer creates a production finding. <!-- swarm-missing #3755/#3758; source-missing #1722 -->
- Rust test discovery covers more cases: a registry in `ripr.toml` (`[analysis.test_harnesses]`) for custom libtest-mimic harnesses, test-case parameterized tests, explicitly configured test attributes, `cfg(all(test, ...))` in any order, and repository-local `include!` fragments. <!-- swarm #3532, #3608, #3634, #3603, #3636, #3522, #3513, #3530, #3213, #3211 -->
- Probe IDs that share a fingerprint get distinct IDs within a run, so suppressions follow the code. <!-- ripr 0.11.0 summary (#1706) -->

## Editor and server distribution

- The extension verifies a downloaded server manifest against the digest shipped in the extension before reading it. It limits download sizes and redirect hosts, and reinstalls a cached server whose recorded digest does not match. <!-- ripr 0.11.0 summary (#1707); source-missing #1717 -->
- Server archives are unpacked by the extension itself instead of the system `tar` or `Expand-Archive`. File-count, size, and compression-ratio limits are checked before any file is written. <!-- source-missing #1718 -->
- The release server manifest now uses schema 2 and contains no hosting URLs. <!-- source-missing #1710 -->
- `exposed` findings now show as warnings, not info, so they are at least as visible as weaker ones. Several settings gained descriptions and minimum values. <!-- swarm #2592; unnumbered VS Code settings entries -->
- The language server adds pull diagnostics, progress reporting, UTF-16 positions, and a versioned diagnostic-code list. It reloads Python configuration when project markers change. It remains an experimental sidecar that analyzes saved files. <!-- swarm #1669, #3012, #2185, #3503, #3576 -->

## Agents and MCP

- `ripr mcp --stdio [--root PATH]` is a read-only Model Context Protocol server that reports workspace status. It cannot edit files or run commands. <!-- swarm #3088, #3525, #3587 -->
- `ripr agent receipt` no longer refuses after a clean `after` phase. Values in generated commands are quoted so a shell cannot expand them. <!-- source-missing #1741; swarm #2347 -->
- The repair docs now cover the governed Python `verify` phase and optional rollback. <!-- swarm-missing #3747 -->

## Windows and PowerShell

- Generated commands come with PowerShell forms where they can be translated safely, and a note where they cannot. A quoted program path is now actually run instead of echoed. `first-pr` recovery commands that redirect output also get PowerShell forms that write UTF-8. <!-- ripr 0.11.0 summary (#1705); source-missing #1727; swarm-missing #3870 -->
- `first-pr` paths print with forward slashes. On Windows, language-server refreshes no longer hang on inherited Git handles. <!-- swarm-missing #3869/#3873; swarm #2430 -->

## Security and supply chain

- Server downloads and archive extraction are hardened as described above. Dependabot now waits 14 days after a release before proposing an update. <!-- source-missing #1717, #1718, #1692 -->

## Upgrade notes

- Some findings may change between `exposed` and `weakly_exposed`, and some declarations now read `static_unknown`. Review baselines and gate thresholds after upgrading. The first run after upgrading re-analyzes instead of using the cache. <!-- #1747, #1751, #3767, #3755/#3758; cache-generation bumps in #3766, #1724, #3530, #3634 -->
- Tools that read server manifest fields directly need the schema 2 fields. Setting `ripr.server.version` explicitly still bypasses the extension's built-in distribution descriptor. <!-- #1710, #1707 -->
- A repair attempt started with an older binary cannot be re-receipted. Start a new attempt with 0.11.0. <!-- #1741 -->
- An internal error now exits with code 2 and prints `ripr: internal error`. Git calls time out after 5 minutes by default (`--git-timeout`, `RIPR_GIT_TIMEOUT`). <!-- swarm #2660, #2613 -->

## Known limitations and non-claims

- ripr is static mutation-exposure analysis. It does not run mutants or report runtime mutation outcomes. Mutation testing remains the runtime backstop.
- Rust gap-repair support is `usable alpha`. Fixture, package, editor, and before/after receipt paths are tested. The governed real-repository corpus has zero eligible attempts, so route yield and success for ordinary users have not been measured. <!-- docs/RELEASE.md; swarm #3077 -->
- TypeScript, JavaScript, and Python evidence remains preview and advisory. It does not gate and is not a claim of parity with Rust.
- The advisory commands and CI output are not merge gates unless a repository adopts one explicitly. The MCP server and language server are read-only.

- Deferred to 0.11.1, which 0.11.0 does not claim (proposed under the narrow cut, pending the final #2766 dispositions):
  - native Windows Job Object ownership of timed subprocess trees and bounded poisoned-LSP initialize (#3803, #3802, #3096);
  - the remaining pre-release Cargo and editor npm dependency upgrades (#3787–#3793, #3813);
  - canonical baseline identity migration (#1964);
  - the stable-absent to RC managed-download fallback (#3798);
  - the independently adjudicated Rust behavior challenge (#3804–#3806);
  - the blind installed agent journey (#3797);
  - the large-repository cache observability and semantic reuse work (#3795, #3796).
