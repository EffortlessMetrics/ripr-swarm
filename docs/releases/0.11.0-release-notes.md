# ripr 0.11.0

ripr 0.11.0 makes the path from a changed behavior to one focused test clearer
and more honest. `ripr check` selects one bounded next action—or names why no
action is currently justified. Repair packets carry the related test, allowed
edit surface, verification route, and before/after receipt. The analysis remains
static: ripr does not run mutants or claim runtime test adequacy.

The release also adds read-only MCP workspace status, targeted reruns, stronger
server-download verification, broader preview-language visibility, and clearer
failure and limitation states. See the
[Terminology bridge](https://github.com/EffortlessMetrics/ripr/blob/main/docs/TERMINOLOGY.md)
for the internal terms used by machine output and deeper reference docs.

## First use and command line

- `ripr check` is the ordinary first-value command. Its bounded human output
  names one selected gap, one safe next action, or an honest no-action/limited
  state, with `--format human-full` and `--format json` for deeper evidence.
- `git diff <base>...HEAD | ripr check --diff -` reads a diff from stdin. A diff
  with no file changes says so instead of quietly reporting zero findings.
  <!-- swarm #2655, #2425 -->
- A mistyped flag suggests the closest flag listed by that command's own help,
  including `explain`, `context`, `cache`, and `first-pr`.
  <!-- swarm #2583, #3812, #3786 -->
- `ripr init --dry-run` checks the same failure boundaries as the real run and
  prints each planned file action before writing. <!-- swarm #2576 -->
- Default `check` output preserves the selected root and diff scope in the
  `explain` and `context` next commands. It no longer prints an empty `Hidden:`
  section. <!-- swarm #2598, #2659, #2571 -->
- `ripr doctor` reports loaded configuration, language availability, tool state,
  and whether first-use artifacts exist. The final release must distinguish
  RIPR's build-from-source MSRV from the analyzed repository's own toolchain.
  <!-- swarm #3866; required repair #3907 -->
- New advisory commands include `ripr rerun`, `plus`, `pr-summary`,
  `pr-evidence`, `annotations`, and `impacted-evidence`. `ripr cache status`
  and `ripr cache clear` manage the analysis cache. None is a merge gate by
  default. <!-- swarm #1520, #1476/#1460/#1468/#1467/#1474, #1822/#2865/#2738 -->
- `check --suppression-policy` and
  `gate evaluate --exception-policy` read committed policy files. Suppressed
  findings remain visible as suppressed. <!-- swarm #1475, #1477 -->
- Unchanged files reuse cached file analysis, and follow-up commands can reuse
  retained results. Cache reuse is evidence-scoped; a hit is not an automatic
  claim that every higher-level result was reused. <!-- swarm #2039, #2322, #2250; #3794 -->

## Analysis and test guidance

- A test counts only when that test is tied to the changed behavior and contains
  a relevant check. Same-file placement or token similarity alone no longer
  earns strong exposure. Some findings that read `exposed` in 0.10 now read
  `weakly_exposed`, with the reason shown. <!-- source #1747, #1751 -->
- Literal Rust `match` arms are credited only when a test calls the code with an
  input that selects that arm. Text in comments and checks for another arm do
  not count. A narrow two-boolean tuple-arm shape can be credited when the test
  asserts the exact input and result. <!-- swarm #3759, #3766, #3767; source #1716, #1723 -->
- When ripr cannot establish a boundary operand, guarded error path, target,
  observer, or other load-bearing fact, it names a limitation instead of
  manufacturing a repair. <!-- source #1724, #1726; #3807 -->
- Changed parameter and struct-field declarations are classified conservatively,
  and the closing brace of an added `#[cfg(test)]` module no longer creates a
  production finding. <!-- swarm #3755/#3758; source #1722 -->
- Rust test discovery covers custom libtest-mimic harnesses registered in
  `ripr.toml`, parameterized tests, configured test attributes,
  `cfg(all(test, ...))` in any order, and repository-local `include!`
  fragments. <!-- swarm #3532, #3608, #3634, #3603, #3636, #3522, #3513, #3530, #3213, #3211 -->
- Probe IDs that share a fingerprint remain distinct within a run, so
  suppressions and follow-up commands keep the intended changed location.
  <!-- source #1706 -->

## Preview languages

- TypeScript and JavaScript diff analysis recognizes `.ts`, `.tsx`, `.mts`,
  `.cts`, `.js`, `.jsx`, `.mjs`, and `.cjs`, with module kind and
  TypeScript/JavaScript counts preserved. All remain preview/advisory.
  <!-- swarm #4094 -->
- Modern module extensions are first-class analysis inputs. The final candidate
  must either make repair, related-test, targeted-rerun, and packet projections
  consume the same extension authority or publish the exact remaining
  limitation. <!-- #4116 -->
- Python static facts remain preview. Selected pytest/unittest shapes can earn a
  bounded repair card only when ripr has the current owner, related test,
  missing boundary/value/effect, test location, verify command, and edit
  boundary. Other Python findings remain inspect-only or limited.
- Preview packaging does not imply Rust parity, merge-gate authority, runtime
  execution, or a support-tier promotion.

## Editor and server distribution

- The extension verifies downloaded server manifests and digests before use,
  limits download size and redirect hosts, and reinstalls a cached server whose
  recorded digest no longer matches. <!-- source #1707, #1717 -->
- Server archives are unpacked by the extension rather than system `tar` or
  `Expand-Archive`; file-count, size, path, and compression-ratio limits are
  checked before writes. <!-- source #1718 -->
- The server manifest uses schema 2 and contains no hosting URLs.
  <!-- source #1710 -->
- `exposed` findings appear as warnings rather than info. Settings gained
  clearer descriptions and minimum values. <!-- swarm #2592 -->
- The language server includes pull diagnostics, progress reporting, UTF-16
  positions, and a versioned diagnostic-code list. It remains an experimental
  sidecar over saved workspace state. <!-- swarm #1669, #3012, #2185, #3503, #3576 -->

## Agents and MCP

- `ripr mcp --stdio [--root PATH]` starts a read-only Model Context Protocol
  server for workspace status. It does not edit files or execute repair or
  verification commands. See
  [MCP server](https://github.com/EffortlessMetrics/ripr/blob/main/docs/interop/mcp.md).
  <!-- swarm #3088, #3525, #3587 -->
- `ripr agent receipt` can finish after a clean `after` phase. Generated command
  values are quoted rather than interpolated as raw shell text.
  <!-- source #1741; swarm #2347 -->
- Repair documentation covers the governed Python `verify` phase and optional
  rollback. <!-- swarm #3747 -->

## Windows and PowerShell

- Generated commands include native PowerShell forms where translation is
  supported, and name the limitation where it is not. Redirecting forms write
  BOM-free UTF-8/LF bytes that match the producer contract.
  <!-- source #1705/#1727; swarm #3870/#3966 -->
- Public paths use stable forward-slash rendering where the schema requires a
  portable repository-relative path. <!-- swarm #3869/#3873, #4097, #4113 -->
- Language-server refresh and bounded process routes close inherited handles and
  retain terminal failure state rather than relying on an outer workflow
  timeout. Final native-Windows qualification remains candidate-bound.
  <!-- swarm #2430; #3922 -->

## Security and supply chain

- Server downloads and archive extraction are hardened as described above.
- Dependabot waits 14 days after a dependency release before proposing an
  update. <!-- source #1692 -->
- The exact Cargo and editor npm graphs, advisories, licenses, package
  inventories, and expiring suppressions remain release inputs; green product
  tests do not replace those graph-specific receipts. <!-- #3787, #3811, #3813 -->

## Upgrade notes

- Some findings may move between `exposed`, `weakly_exposed`, and conservative
  limited states. Review baselines and any adopted gate thresholds after
  upgrading. The first run after a cache-generation change re-analyzes instead
  of trusting incompatible cached semantics.
- Tools that read server-manifest fields directly must use schema 2. Setting
  `ripr.server.version` explicitly still bypasses the extension's built-in
  distribution descriptor. <!-- source #1710, #1707 -->
- A repair attempt started with an older binary cannot be re-receipted. Start a
  new attempt with 0.11.0. <!-- source #1741 -->
- An internal error exits with code 2 and prints `ripr: internal error`. Git
  calls time out after 5 minutes by default and can be bounded with
  `--git-timeout` or `RIPR_GIT_TIMEOUT`. <!-- swarm #2660, #2613 -->

## Known limitations and non-claims

- ripr is static mutation-exposure analysis. It does not run mutants or report
  runtime mutation outcomes. Mutation testing remains the runtime backstop.
- The Rust gap-repair transaction is `usable alpha`. Package, editor, bounded
  packet, and before/after paths exist when RIPR emits a complete route.
  Governed real-repository route yield and ordinary-user success are not yet
  established for broad use. <!-- #3797, #3804 -->
- TypeScript, JavaScript, and Python evidence remains preview/advisory and does
  not gate by default or claim parity with Rust.
- The advisory commands and generated CI are not merge gates unless a
  repository explicitly adopts a gate policy. MCP and the language server are
  read-only unless a separately governed capability says otherwise.
- `ripr review-comments --gap-ledger` is not described by the published
  `review-comments.schema.json` unless the final #3920 packet lands a schema
  branch for that producer. The default and `--check-output` routes are
  schema-covered. <!-- #3913; final disposition required under #3920 -->

## Install

Cargo installation builds ripr locally and therefore requires Rust 1.95 or
newer:

```text
cargo install ripr --version 0.11.0 --locked
```

RIPR's build MSRV is not a minimum compiler version for repositories analyzed
by an already-built release binary. Project verification continues to use the
target repository's own selected toolchain.

- VS Code: install `EffortlessMetrics.ripr` from VS Marketplace or Open VSX.
- Server archives, the server manifest, checksums, and the VSIX are attached to
  the [GitHub Release](https://github.com/EffortlessMetrics/ripr/releases/tag/v0.11.0).
