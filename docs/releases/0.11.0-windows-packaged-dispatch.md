# RIPR 0.11.0 Windows packaged dispatch checklist

Status: **read-only staging checklist for [#9274](https://github.com/EffortlessMetrics/ripr-swarm/issues/9274)
C4, written 2026-10-31.** It lists the inputs and expected shape of one
`Windows Packaged Qualification` run. It selects no candidate, creates no ref,
and records no result. The run itself is C5 and is tracked on
[#2769](https://github.com/EffortlessMetrics/ripr-swarm/issues/2769).

This file is a stage-specific companion to
[`0.11.0-cut-checklist.md`](0.11.0-cut-checklist.md), which owns operation
order. If the two disagree, that checklist, the workflow source and the owning
issues win. The lane contract and claim boundary live in
[`WINDOWS_PACKAGED_QUALIFICATION.md`](../WINDOWS_PACKAGED_QUALIFICATION.md).

## Preconditions

- [ ] The immutable candidate ref exists on `origin` (created by
      [#1609](https://github.com/EffortlessMetrics/ripr-swarm/issues/1609)). This
      checklist never creates it; do not create a tag to rehearse this route.
- [ ] The selected candidate commit is read back from that ref, not copied from a
      branch tip or a previous run.
- [ ] No source or package surface has changed since the candidate was pinned; a
      changed surface needs a successor candidate and a fresh run.

## Dispatch inputs

Source: `.github/workflows/windows-packaged-qualification.yml`
(`workflow_dispatch`, `contents: read`, no secrets, 120-minute job timeout,
concurrency group per `candidate_sha`, no cancellation).

| Input | Qualifying run | Value |
| --- | --- | --- |
| `candidate_sha` | required | Full 40-character commit SHA of the pinned candidate. |
| `candidate_ref` | required | `refs/tags/ripr-release-0.11.0-<40-hex>`, where the suffix equals `candidate_sha`. |
| `rehearsal` | `false` (default) | Leave unset. `true` accepts only `refs/heads/rehearsal/windows-packaged-<40-hex>` and marks the receipt NON-QUALIFYING. |

- [ ] Dispatch from the workflow definition that belongs to the candidate
      process (the run checks out `candidate_sha`, not the dispatching branch).
- [ ] Record the dispatch time, run id and run attempt on
      [#2769](https://github.com/EffortlessMetrics/ripr-swarm/issues/2769) before
      waiting on the result.

## Expected jobs and steps

One job, `qualify` ("exact candidate packaged journeys"), on `windows-latest`.
Read each step's own conclusion, not only the run conclusion.

1. Receipt root initialised outside the checkout (before and after checkout).
2. Checkout of `candidate_sha`.
3. `Verify candidate and ref identity`: ref shape, ref suffix equals SHA, `HEAD`
   equals SHA, `git ls-remote` of the ref resolves directly to the same SHA.
4. Rust 1.95.0 and Node 24 setup; isolated Cargo home, target and temp
   directories.
5. `Package and install exact crate`: `cargo package -p ripr --locked`, install
   from the extracted crate into a runner-temp prefix; crate and binary SHA-256
   recorded.
6. `Run isolated packaged CLI journey`: `version`, `help`, typed
   `doctor --json`, `check`, `explain`, `context`, `pilot`, `outcome`.
7. `Package exact VSIX and inspect contents`.
8. `Run trusted packaged editor journey` (default Rust, full seam, TypeScript
   preview, restart, shutdown, process cleanup).
9. `Run untrusted trust-boundary journey`. **Watch this step first.** It is the
   journey named in [#9274](https://github.com/EffortlessMetrics/ripr-swarm/issues/9274)
   as the one that failed in earlier runs. It runs with
   `RIPR_TEST_WORKSPACE_TRUST=untrusted`, has a 30-minute step timeout, and
   fails the job if any process whose command line belongs to the lane remains
   afterwards.
10. `Retain editor host logs` (redacted), `Write Actions-only qualification
    receipt`, and `Upload Actions-only receipts` (all `if: always()`).

## Reading the result

- [ ] Artifact `windows-packaged-qualification-<candidate_sha>` exists
      (upload fails the step if empty).
- [ ] The receipt records `rehearsal: false`, the same `candidate_sha` and
      `candidate_ref` that were dispatched, and `publication` and `secrets` as
      `forbidden`.
- [ ] Crate, binary and VSIX SHA-256 digests are present, and
      `receipt-file-digests.json` covers the retained files.
- [ ] `editor-trusted.log` and `editor-untrusted.log` are both present; a
      missing log is a missing journey, not a pass.
- [ ] On failure, name the failing step and the log that shows it. Keep source
      failure, test failure and runner or infrastructure failure separate; do not
      rerun unchanged to turn red into green.

## Claim boundary

A green run says the named candidate artifacts were built and these Windows
packaged journeys emitted the retained evidence. It does not qualify the
release, establish product correctness or mutation adequacy, or authorize
source integration, tagging, signing, publication or merge. The last recorded
qualifying run (`31568726201`, 2026-08-12, head `83217e97`) is history for a
different candidate and is not evidence for this one.
