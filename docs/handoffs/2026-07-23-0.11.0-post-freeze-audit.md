## Trust disposition

Landed trust work is required for 0.11.0:

- complete gap-ledger routes carry producer-owned seam identity;
- explicitly configured blocking is command-boundary tested while defaults remain advisory;
- typed `CommandSpec` descriptions remain route metadata, not execution authority;
- repo-exposure artifacts are producer-, repository-, revision-, input-, and content-bound;
- static movement and executed verification use separate assurance axes;
- `VerificationExecutionResultV1` exists as a validated contract without implying a runner exists;
- receipt writers bind actual Git HEAD and reject mismatched assertions;
- receipt issuance revalidates canonical verify input and recomputes movement;
- default receipt paths are portable and bounded.

Open `ripr-swarm#2332` through `#2334` are deferred. Therefore 0.11.0 must state plainly:

- RIPR does not yet execute the verification command on the user’s behalf;
- `RepairReceiptV2` is not part of this release;
- a static-only receipt is not runtime verification, correctness proof, coverage adequacy, mutation adequacy, or merge approval.

## Editor and LSP disposition

The coherent editor reliability groups are required together:

1. diagnostic budget enforcement, omission disclosure, legitimate-zero behavior, and one stored push/pull selection;
2. debounce, saved-content deduplication, dirty-buffer quarantine, and saved-workspace currentness;
3. real-binary lifecycle, work-done progress, Git and refresh deadlines, and one terminal outcome;
4. transport and payload bounds, typed client-feature negotiation, configuration authority, protocol tracing, and typed degradation;
5. versioned action data, fail-closed command rejection and resolve, and real-wire compatibility journeys;
6. Workspace Trust, multi-root transitions, server startup and resolution, download disclosure, command menus, and first-run onboarding.

Splitting these groups would recreate stale, partial, or client-dependent behavior that the later work explicitly removed. Convenience-only copy changes carry no independent support claim, but they remain in the exact integrated candidate.
