# Selected-work identity corpora (RIPR-SPEC-0244, #1706)

Captured corpora for the shared selected-work identity law checker in
`xtask/src/work_selection_identity.rs` (#1706, delivery slice PR A). The
checker validates `SelectedWorkIdentityV1` packets against a
`PortfolioBasisV1` compiled from immutable captured inputs; it selects no
work, grants no authority and mutates nothing. `author_corpus.py`
regenerates `corpus.json`, the captured variants and `provenance.json`
after an intentional change; `cargo xtask check-fixture-contracts`
recomputes the provenance digests fail-closed.

## Layout

- `corpus.json` — the twelve #1706 required scenarios. Each scenario names
  the captured portfolio directory it binds against (either a
  `fixtures/work_portfolio` corpus or a local `captured/` variant) and one
  or more selection cases. A case carries a `SelectedWorkIdentityV1`
  packet (or a legacy compatibility packet), the expected outcome
  (`pass`/`fail`), the exact expected law/route pairs for failures, and the
  frozen plan disposition the PR C planning consumer will later emit.
- `captured/multi-campaign/` — canonical inputs with issue `9105` placed in
  both the editor-ux and rust-repair campaigns (scenario 2).
- `captured/standalone/` — canonical inputs with issue `9106` removed from
  every campaign record (scenario 3).
- `captured/overlap-introduced/` — canonical inputs plus open PR `8899`
  linked to issue `9105` with its own branch and worktree (scenario 8).
- `provenance.json` — per-file SHA-256 bindings in the RIPR-SPEC-0223
  provenance convention.

## The twelve #1706 required scenarios

1. `scenario-01-selected-issue-one-campaign` — issue `9105` selected for
   `start_build` as a member of `campaign-rust-repair`.
2. `scenario-02-selected-issue-several-related-campaigns` — the same issue
   selected while belonging to two related campaigns.
3. `scenario-03-standalone-no-campaign-placement` — issue `9106` is valid
   standalone work with zero campaign references.
4. `scenario-04-two-campaigns-independent-disjoint-resources` — issues
   `1693` and `9105` selected independently with disjoint writer
   resources.
5. `scenario-05-existing-open-pr-selected-for-repair` — issue `9101` binds
   open PR `8801` for `repair_review` instead of a new build.
6. `scenario-06-legacy-writer-authorization-fails` — a legacy
   active-goal/current-work-item packet attempting `writer` authority must
   fail with `legacy_compatibility`/`reject_legacy_authority`.
7. `scenario-07-snapshot-change-issue-head-compatible` — the stale-local
   portfolio variant keeps the same default-branch head; the selection
   stays compatible while the snapshot identity changes.
8. `scenario-08-overlap-introduced-forces-reconcile` — the new PR `8899`
   overlap forces `overlap_visibility`/`reconcile_selection`.
9. `scenario-09-wrong-identities-fail-visibly` — wrong repository, issue,
   action, basis, worktree and head each fail with their exact law/route.
10. `scenario-10-burndown-partial-acceptance-uncovered` — issue `9109`
    stays `acceptance_uncovered` after merged PR `8806`.
11. `scenario-11-fresh-root-resume-from-artifacts` — the selection resumes
    from committed artifacts only; a legacy active-goal ref resolves as a
    read-only historical campaign reference.
12. `scenario-12-narrow-single-agent-despite-active-campaigns` — issue
    `9202` stays single-agent while unrelated campaigns stay active.
