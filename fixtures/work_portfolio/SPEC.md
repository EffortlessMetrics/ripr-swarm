# Work portfolio captured corpora (RIPR-SPEC-0234, #1704)

Deterministic captured-input corpora for the read-only work-portfolio
compiler in `xtask/src/work_portfolio.rs`. The compiler never reads live
GitHub, local or cargo-allow state; these committed bytes are the authority
it compiles from. `author_corpus.py` regenerates every corpus and
`provenance.json` after an intentional change; `cargo xtask
check-fixture-contracts` recomputes the provenance digests fail-closed.

## Layout

- `corpus/` — the canonical captured directory (all seven sources observed
  and current).
- `variants/unix_root/` — byte-equivalent inputs with Unix-style root
  spelling; must compile to byte-identical normalized JSON.
- `variants/reordered/` — the canonical inputs with every JSON array
  reversed; must compile to byte-identical normalized JSON.
- `variants/missing_github/` — `issues.json`, `pull_requests.json` and
  `claims.json` absent with matching manifest states; every candidate must
  degrade to `not_proven` while campaigns stay visible.
- `variants/stale_local/` — `local_state.json` observed older than the
  capture window; candidates with local relationships must degrade to
  `partial`.
- `variants/no_cargo_allow/` — `cargo_allow.json` absent and marked
  `unavailable`; requirement-linked candidates must degrade to `partial`
  and duplicate-family evidence must be flagged as weakened.
- `provenance.json` — per-corpus, per-file SHA-256 bindings in the
  RIPR-SPEC-0223 provenance convention.

## The twelve #1704 required scenarios (all in the canonical corpus)

1. Several durable campaigns with eligible issues in different surfaces:
   `campaign-rust-repair` (Rust CLI surface) and `campaign-editor-ux`
   (editor surface) both carry eligible issues; `campaign-infra-hardening`
   (CI surface) carries none.
2. One full/conflicting lane and one independent available lane: the
   rust-repair lane is occupied and later collision-marked; the editor-ux
   lane stays available.
3. Issue `9104` is blocked on the external dependency
   `cargo-allow#upstream-0.9`.
4. Issue `9101` has open PR `8801`.
5. PR `8801` carries unresolved review findings (repair-review), PR `8802`
   waits only on checks (resume), PR `8803` is merge-ready (approved with
   successful checks).
6. Issue `9107` carries the colliding active exclusive claims
   `claim-9107-a`/`claim-9107-b`; PR `8804` heads the local branch
   `feat/work-9108` with no registered claim (unregistered branch/PR
   collision).
7. Issues `9105` and `9106` form the duplicate family around
   `REQ-dup-family` with distinct and overlapping semantic slices.
8. Missing GitHub data, stale local data and an unavailable cargo-allow
   graph are the three `variants/` corpora above.
9. Windows/Unix root equivalence and reordered inputs are the
   `variants/unix_root` and `variants/reordered` corpora.
10. `campaign-infra-hardening` has no eligible current work and must not
    hide the other campaigns.
11. Issue `1693` (preview projection honesty, editor campaign) and the
    Rust repair campaign are visible simultaneously with no default
    campaign synthesized.
12. Issue `9202` is explicitly `single_agent_preferred` because
    orchestration cost dominates.


Commit the regenerated bytes together with any SPEC.md/scenario-pin change.
