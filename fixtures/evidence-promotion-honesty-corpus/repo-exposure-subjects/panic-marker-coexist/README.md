# Producer-owned panic marker controls

The sibling `panic-marker-neutral` and `panic-marker-collision` subjects
differ only in their ordinary weak test's name. Neither contains a panic
attribute or snapshot. Both must retain three weak seams without a panic or
framework limitation; a source identifier supplies no producer marker.

This subject has a genuine assertion-free `#[should_panic]` witness and an
unread `with_settings` snapshot of the same owner's value. The field seam
keeps its real panic limitation, original class and stage states. The
framework adapter must preserve that established marker and its reason.
The return seam remains independently unknown and receives neither marker.

Case assertions are authored separately from native reports and require
exactly one matching seam for each explicit present or absent category.
Reports are captured unchanged from the candidate executable. These cases
do not evaluate snapshot bytes or establish arbitrary receiver identity.
