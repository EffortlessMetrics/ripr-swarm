# Field snapshot recommendation controls

These six static analysis subjects cover #13278 under #8121. They do not run
Insta or evaluate snapshot bytes. Each has two field-construction seams and
one return-value seam. The field classes and five stage states stay fixed;
the new expectation concerns the existing typed framework limitation.

| Subject | `id` marker | `items` marker | Independent preservation control |
| --- | --- | --- | --- |
| `field-snapshot-settings` | present | present | Unread settings name uncertainty for both fields |
| `field-snapshot-literal` | absent | present | Literal `.id` redaction keeps that field's gap |
| `field-snapshot-weak` | absent | absent | Ordinary weak assertions remain selectable |
| `field-snapshot-exact` | present | absent | A real snapshot cannot defeat the exact `items` assertion's strong grip |
| `field-snapshot-other` | absent | absent | The snapshotted object is independently constructed |
| `field-snapshot-inline` | absent | absent | Ordinary inline snapshots retain their existing disposition |

The return seam must never acquire this marker. Return-value recommendation
semantics are outside the child. The `other` control is a genuinely unrelated
operand; it does not claim that the bounded shared reader resolves every
same-named callee. A test that separately calls the free owner and snapshots a
same-named method result can still lead that reader to conservative uncertainty.
That inherited false withholding remains a residual under #8121.

Each case combines `expected_repo_seam_grip` with
`expected_repo_seam_limitation`. The latter pins the named category's presence
or absence on exactly one matching seam; missing or malformed evidence and
ambiguous selectors fail. The report freshness guard compares limitation
stage, state and category, so deleting a marker cannot hide behind unchanged
grip classes. Re-blessing a marker-free report still fails the independent
case expectation.

Full reports are captured by the candidate's actual native executable and
retained byte for byte, including producer artifact metadata and display
routes. They are regenerated by the normal honesty gate from the declared
`report_subject`. They must never be hand-edited to adjust marker or cache
generation values. Pilot/brief selection, accurate explanation, exact-stage
controls and warm-cache behavior are covered by the associated native CLI
test and proof receipt.
