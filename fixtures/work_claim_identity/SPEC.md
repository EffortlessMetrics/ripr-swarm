# Selected-work durable-claim corpora (RIPR-SPEC-0270, #1706)

Corpus for the durable-claim binding consumer in
`xtask/src/work_claim_identity.rs` (#1706, delivery slice PR B, consuming
#1635/#1647). The check validates committed `WorkClaimV1` rows against a
`PortfolioBasisV1` compiled from immutable captured inputs; it selects no
work, authorizes no writer, performs no release or takeover, and mutates
nothing. `check-fixture-contracts` recomputes the provenance digests
fail-closed.

## Layout

- `corpus.json` — the five required scenarios. Each scenario names the
  captured portfolio directory it binds against (referenced, never
  duplicated) and one or more claim cases evaluated in order: claims that
  pass join the scenario's committed claim set and constrain later claims.
  A case carries a `WorkClaimV1` row, the expected outcome (`pass`/`fail`)
  and the exact expected law/route pairs for failures. Every claim embeds
  the full `SelectedWorkIdentityV1` it binds, so the RIPR-SPEC-0244
  selection laws run inside the claim check before the claim-level and
  interaction laws. Claims that occupy a writer worktree record that
  worktree in the selection overlaps.
- `provenance.json` — per-file SHA-256 bindings in the RIPR-SPEC-0223
  provenance convention under the `work_claim_identity_provenance.v1`
  schema version.

## The five scenarios

1. `claim-01-writer-claims-for-distinct-selections-pass` — three writer
   claims for three distinct selections on three distinct worktrees pass.
2. `claim-02-standalone-selection-claim-passes` — a standalone selection
   with zero campaigns is claimable.
3. `claim-03-stale-basis-reconciles-without-takeover` — a worktree
   conflict reconciles without release or takeover; a stale basis keeps
   the claim recorded as `stale_requires_reconcile`.
4. `claim-04-double-claim-of-one-selection-fails` — one selection cannot
   be claimed by two worktrees; the first claim stays active.
5. `claim-05-legacy-claim-read-only-migration-posture` — legacy refs
   resolve read-only with migration posture and no authority; a
   mismatched legacy work-item ref fails.
