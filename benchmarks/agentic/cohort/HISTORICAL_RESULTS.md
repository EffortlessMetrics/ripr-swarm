# Historical cohort observations (2026-11-04)

These tables are retained from #13071's original pilot documentation. Their cells
are unchanged. Raw receipts and generated scoreboards also retain their original
bytes. The pre-v3 scorer counted timeouts and some other process failures as
catches and could admit empty test execution or a changed grading checkout.
The captures do not establish which runs, if any, were affected. These are
**unrequalified historical observations**, not current efficiency baselines.

Reading these receipts with today's reporter does not recreate missing native
execution evidence. Model aliases, old executable versions and small cohorts
also limit comparison. Regrade retained artifacts or rerun with the current
qualified instrument before using quality outcomes as acceptance evidence.

## First pilot: RIPR 0.10.0, 99 recorded runs

The original suite contained eight hand-written tasks and three larger mechanical
mutation tasks. The reported mean escape rates, token volumes and elapsed times
were:

| Model | Arm | Runs | Escape rate | Runs with any escape | Turns | Tokens | Wall s |
|---|---|---|---|---|---|---|---|
| Haiku | none | 22 | 0.4% | 3 | 5.2 | 202k | 30 |
| Haiku | `ripr check` | 22 | 0.7% | 4 | 6.6 | 280k | 34 |
| Haiku | `ripr agent brief` | 22 | 0.7% | 4 | 13.5 | 712k | 60 |
| Sonnet | none | 11 | 1.4% | 2 | 5.0 | 197k | 24 |
| Sonnet | `ripr check` | 11 | 0.2% | 1 | 6.4 | 266k | 29 |
| Sonnet | `ripr agent brief` | 11 | 1.7% | 3 | 5.6 | 250k | 29 |

The original author described a ceiling effect and approximately 3.5 times the
Haiku token volume for the brief loop. Those descriptions remain scoped to this
old instrument; they establish neither a causal benefit nor its absence.

## strsim configuration matrix: the same development build

The original follow-up contained 100 new records and reported the following
escape-rate point estimates and nominal p-values. The none/check/brief cells
also incorporated their earlier two runs. The p-values are historical, involve
many uncorrected comparisons and are not reproduced by the current reporter.

| Config | Haiku (none 9.0%) | Sonnet (none 17.7%) |
|---|---|---|
| `ripr check` | 8.1% | 22.7% (p<0.01) |
| `ripr check --json` | 8.3% | 17.0% |
| `ripr check --mode fast` | 18.3% (p=0.03) | 22.6% (p=0.01) |
| `ripr agent brief` | 14.3% | 18.6% |
| `ripr agent brief --max-seams 1` | 14.3% | 19.6% |
| `ripr agent brief --max-seams 10` | 17.4% (p=0.05) | 25.2% (p=0.02) |
| `ripr agent brief`, optional use | 9.1% | 30.0% (p<0.01) |
| MCP, no `base` | 12.6% | 39.6% (p<0.01) |
| MCP, `base: HEAD~1` | 7.0% (p=0.60) | 25.7% (p=0.03) |

Some point estimates are lower and others higher than control; none of this
unrequalified, small-sample table establishes a reproducible efficiency win.
The historical optional-use and MCP base findings remain traceable to #13050
and #13096. They are not assertions about current binaries or providers.

## Retention and interpretation

The frozen first-party tasks, selected mechanical mutant lists, JSONL records
and generated historical JSON/Markdown files are preserved as inputs and history.
The live report is generated by `harness/scoreboard.py`; `harness/agg.py` now
prints that same report rather than calculating a valid-only alternative.
Missing usage, unmatched observations and unverified quality stay explicit.
The [core](CORE_CONTRACT.md) and [collection contract](MEASUREMENT_CONTRACT.md)
define the current semantics. No experiment result is improved by editing prose.
