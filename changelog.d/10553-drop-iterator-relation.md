- A changed `Drop::drop` or `Iterator::next` impl is now related to a same-file test that drops an owned value of the type before an assertion, or drives an owned value through a `for` loop or a consuming adaptor. The relation does not raise a class by itself: with an exact assertion that the sibling-effect oracle cannot confirm the finding is `static_unknown` rather than `weakly_exposed`, an assertion that reads a cell the iterator or guard writes is credited, and a leak (`forget`, `ManuallyDrop`, `leak`), a lazy adaptor, an inherent method of the same name or a redeclared type relates nothing. `shape-iterator-next-collect` moves from `weakly_exposed` to `static_unknown` (RIPR-SPEC-0240, #10553).
