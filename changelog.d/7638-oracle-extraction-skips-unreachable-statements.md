- Rust oracle extraction no longer reports test statements that never run as related-test oracles: an `unwrap()`/`expect()` or uncompared `unwrap_err()`/`expect_err()` reading, a custom assertion helper or a weak assertion inside an `if false`/`if !true`/`while false` block, inside a `let`-bound closure that is never named again, or after an unconditional `return`; and any oracle, a strong `assert_eq!` included, after an unconditional `panic!`, `unreachable!`, `todo!`, `unimplemented!` or `process::exit(..)` in the same block. Before, `if false { check(300).unwrap_err(); }` read as `broad_error` / weak, and a finding whose only check follows `std::process::exit(0);` read `weakly_exposed`; it now reads `reachable_unrevealed`. A strong `assert_eq!` or `assert!` in the first three shapes keeps its existing "not credited" refusal from execution admission. The parser and lexical adapters apply the same reading (RIPR-SPEC-0231 rule 8). It is conservative: other constant conditions, macro input, unbalanced text and lines that also hold a reached statement keep their existing credit, and the change only removes oracles, so it cannot make a finding `exposed` (#7638).
