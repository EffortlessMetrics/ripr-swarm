- Python: the call-site lexer keeps a call inside a multiline triple-quoted f-string replacement field visible and treats a CRLF after a backslash as one line break, so a CRLF-continued string no longer exposes its continuation line or opens a fictitious triple-quoted region (#8787). Literal format-spec text after a field's top-level `:` and a nested different-delimiter triple-quoted literal stay hidden. A nested f-string in a field exposes only its real fields. A backslash before a brace is a literal character. A `#` comment, the string's own delimiter, or same-quote nesting in a single-line f-string inside a field makes the scanner hide the rest of the text. Pre-existing and unchanged: top-level single-line f-strings using 3.12 same-quote nesting or a newline inside a field can expose text that is not a call (follow-up #9230). Any non-ASCII character adjacent to a name is treated as part of the identifier, so the name is not credited as a call; this is a miss, never a credit, for non-identifier characters such as `×` or NBSP, which cannot appear in valid code outside strings and comments. The fail-closed limit detectors also change: patch or lambda mentions inside strings or comments directly after a non-ASCII character no longer keep the limit.
