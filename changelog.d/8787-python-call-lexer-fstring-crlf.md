- Python: the call-site lexer keeps a call inside a multiline triple-quoted f-string replacement field visible and treats a CRLF after a backslash as one line break, so a CRLF-continued string no longer exposes its continuation line or opens a fictitious triple-quoted region (#8787). Literal format-spec text after a field's top-level `:` and a nested different-delimiter triple-quoted literal stay hidden. A nested f-string in a field exposes only its real fields. A backslash before a brace is a literal character. A `#` comment, the string's own delimiter, or same-quote nesting in a single-line f-string inside a field makes the scanner hide the rest of the text. Pre-existing and unchanged: top-level single-line f-strings using 3.12 same-quote nesting or a newline inside a field can expose text that is not a call (follow-up #9230). A non-ASCII character before an ASCII name is part of the identifier, so an accented or Greek prefix no longer lets the suffix count as a call of the changed owner.
