- Owner-pin no longer refuses an expected value merely because a `let` type annotation names the word (`let e: crate::Config`, `&Config`, `(Config, u8)`), because the word only indexes another place (`v[expected] = ..`, `v [expected] = ..`), or because a `let` value built only of literals, tuples/arrays of literals and `[literal; N]` is shared-borrowed into a call (`Some(&x)`, `helper(f(4), &x)`). Statics, cells, mutexes, struct literals, constructor calls, ranges and every other write shape still refuse, as do keyword-led array assignments (`match [e, o] = ..`); `.replace`, `.take` and `.lock()` over-refusals stay open on #8795 because they need receiver type information (#8795).
