- A Rust `bool` owner whose whole tail is one pure `&&` or `||` chain (`x == 0 && y == 0`, `day % 7 == 6 || day % 7 == 0`) can now be confirmed by an `assert_eq!` pin, but only when some pinned call evaluates every operand: on that run (a literal call, a constant-row table row, or a check helper's call) every operand but the last takes the value that does not short-circuit. A pin whose inputs stop at the first operand, an operand that calls, indexes, casts or can overflow, and a chain mixing `&&` with `||` still leave the gap, as RIPR-SPEC-0197 specifies (#7969).
