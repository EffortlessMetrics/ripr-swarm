<!-- section: Changed -->
- Refusals and failures are machine-readable under a JSON request (#11584). A `check --json` refusal document now carries `status: "refused"` and `error: {code, message, next}` (reason code, the stderr diagnostic, the one command to run), so it can no longer be read as a clean result; completed runs carry neither key. Argv usage errors (`unknown_argument`, `unknown_value`, `unknown_command`) and `context` selector misses write one standalone `cli_refusal` document (`schemas/ripr/cli-refusal.schema.json`) to stdout under `--json` or a JSON `--format`, with the exit code and stderr prose unchanged; without a JSON request stdout stays empty.
- `ripr repair` and `ripr continue` accept `--json`: `repair` prints the agent packet with `repair_attempt.attempt_id` (or the attempt status document when an attempt already awaits its edit), `continue` prints the after-phase document, and their own refusals print the `cli_refusal` document with a next command (#11584).
- `ripr help --json` reports `json_support: true` for `repair`, `continue` and `agent repair`, and their `exit` object says stdout carries the refusal document under `--json` (#11584).
