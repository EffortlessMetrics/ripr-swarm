- A panic inside any MCP tool handler other than `ripr_refresh` is now contained: the call answers a typed `analysis_failed` tool failure naming the tool and a next step, and the `ripr mcp` stdio session keeps serving instead of ending. State a handler wrote before the panic persists; the one mutating handler, `ripr_prepare_repair`, now records `superseded` tombstones before evicting stale transactions, so an old attempt never turns into `attempt_not_found` after a contained panic. `ripr_refresh` is excluded because worker and adapter panics are already contained at the analysis boundary; glue panics in `ripr_refresh` itself, `resources/read`, `tools/list` and `initialize` are not covered (#11116).
