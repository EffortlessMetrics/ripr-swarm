- A changed range bound whose values feed an absorbing consumer (`(0..n).sum()` to `(0..=n).sum()`, `(0..10).contains(&x)` to `(0..=10)`, a match range pattern `0..=5` to `0..5`, a moved range start) no longer reads `exposed` when the only test asserts an input where the old and new ranges give the same result, such as `sum_to(0)`. Such a test now reads `weakly_exposed`; an absorbing range ripr cannot evaluate at the test's inputs reads `infection_unknown`, except a moved match range pattern whose arms ripr cannot read, which keeps the arm-routing reading. Ranges feeding length-preserving chains (`.collect()`, `.iter().map(..)`, slicing) keep the ordinary reading; a set collect or an input where both ranges are empty can still absorb the change there, a known limit (#14419).
