- An integration test that calls a library entry through its module path (`my_crate::inner::entry(..)`, no `use`) is now related to the entry's changed private helper, like the imported spelling already was. It stays unrelated for module paths that are not the entry's exact path, packages with a `#[path]` remap, modules a binary also declares, modules declared other than exactly once or under `cfg`/`cfg_attr`, a test crate that declares a module named like the library or invokes an `include`-family macro, and calls whose path appears only inside a multiline string or comment. A bare call after an own-looking import is refused when that library name is aliased, globbed or redeclared in the test file (#8999). The imported bare-call route is also narrower than before: it now refuses a `self::`/`crate::`/`super::` import of the entry (except `crate::` from a `src/` unit test), a same-named `const`/`static` in the test file, a path whose suffix is not the entry's module path (a re-export tail), an extern-crate alias, a test-crate re-export, and a library whose cfg, `#[path]` or declaration chain does not bind the module to the entry's file, a nearer function-local binding of the entry's name, and a binary-only package with no library (#8999).
