- TypeScript: in a replacement block whose removed and added line counts differ, an added line now pairs with a removed line when each is the other's single best match. Lines are compared by their code tokens, with string literals and comments left out. Before, only the block's first added line found an old line, and that was the block's first removed line, often a comment. Deleting or adding a comment beside a message-only `throw` change no longer hides it from the RIPR-SPEC-0243 rule 4 guard: a check that passes on both messages reads `weakly_exposed` instead of `exposed`. A tie pairs nothing by content, and the block's first added line then keeps the first removed line as before. The annotation-only and new-declaration guards now read the same pairing. A type-only change on a later line of an equal-length block, or on a line of an uneven block that pairs, yields no probe. The new-declaration guard now also skips the opening line of a new function whose counterpart does not resemble it, for example a function that replaces a comment. Content pairing skips blocks over 65,536 line pairs and lines over 256 tokens (#7524).
