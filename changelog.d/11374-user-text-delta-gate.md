- `cargo xtask check-user-text` now gates golden banned-term counts per file on the PR's own delta against the merge-base (read through Git objects): any `(file, term)` that rises fails, a file new at the head counts in full, and removals in one file never offset another, so parallel merges no longer turn `main` red and PRs no longer edit `policy/user-text-baseline.toml`. Golden totals above their ceiling are a reported warning, live surfaces keep absolute ceilings, and an unreadable merge-base falls back to absolute ceilings with a `git fetch --deepen` message. Under CI, pull_request and merge_group runs bind the base to the verified GitHub event identity and read the head from HEAD's blobs, failing closed on mismatched identities or dirty golden paths. The gate logic is reviewed by hand and golden ceilings are warnings on `main` until follow-up issues land a self-qualifying check and a main-side backstop (#11374).
