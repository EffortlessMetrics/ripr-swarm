- A `&mut self` method that assigns a field (`self.n = 1`) now reads `exposed` when a test calls it on a receiver and then asserts that receiver's field exactly (`c.reset(); assert_eq!(c.n, 1);`), instead of `reachable_unrevealed` or `static_unknown`. The receiver may be built as a crate-qualified struct literal through the package's own unshadowed library name (`let mut c = krate::Counter { n: 5 };`), and the field name no longer has to be long enough to count as a token match; a read of another binding or field, a rewrite or rebinding before the read, or a foreign or locally shadowed crate name still keeps the gap open (#14407). The exact field read also no longer confirms a write when the test seeded that field with the expected value before the call (`Counter { n: 1 }`, `c.n = 1;`, a shorthand or `..base` field), when the test file declares or aliases its own type of the owner's name, or when an in-file test shares the owner's file with a second type of that name. Without a token match on the field name, the exact read credits only a receiver built by one visible struct literal: a receiver from a constructor or other call (`Counter::new()`) keeps the gap, since ripr does not read the field value a constructor leaves. That credit also needs the literal's seed and the asserted value to be different plain literals, and no other use of the receiver before the call (a setter, reassignment, `&mut` alias or earlier assertion keeps the gap), an owner whose changed write is its only touch of that field, and a test that binds the owner's own type by name (an import of another crate's or module's same-named type, or a glob from outside the package, keeps the gap). A float seed or expected value keeps the gap too.
