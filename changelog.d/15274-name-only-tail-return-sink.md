- A returned ordering comparison of one parameter against a constant (`n >= LIMIT`) now reaches the return sink, so a test that pins the result at the boundary (`assert_eq!(over_limit(LIMIT), true)`) reads its `return_value` finding as `exposed`. Before, that finding stayed `propagation_unknown` with an unknown sink whatever the tests asserted, while the `predicate` finding on the same line read `exposed`, and `verify` stayed refused. The literal spelling `n >= 1000` already read this way. The reading holds only for `<`, `<=`, `>` and `>=`, and only when the comparison reads exactly one parameter, which the body does not rebind, against constants or other items; an equality over names (`a == b`), two parameters (`width <= limit`), a field (`n >= self.max`) and a local (`let end = ..; end >= start`) stay `propagation_unknown` (#15274).
- A tail `if` whose arms are paths, such as the unit variants in `if n > 10 { Level::High } else { Level::Low }`, now reaches the return sink like one whose arms are literals. A test that pins the variant at the boundary reads the `predicate` finding as `exposed` instead of `propagation_unknown`. A test that pins only a value far from the boundary still reads `weakly_exposed` in both shapes. The reading needs the whole `if` and both arms on one line, opening their own statement, and arms whose paths end in different names; arms on their own lines, an `if` that is one operand of a wider expression, and `Level::High` against `crate::Level::High` stay `propagation_unknown` (#15274).
