- A returned comparison whose operands are all names (`n >= LIMIT`) now reaches the return sink, so a test that pins the result at the boundary (`assert_eq!(over_limit(LIMIT), true)`) reads its `return_value` finding as `exposed`. Before, that finding stayed `propagation_unknown` with an unknown sink whatever the tests asserted, while the `predicate` finding on the same line read `exposed`, and `verify` stayed refused. The literal spelling `n >= 1000` already read this way (#15274).
- A tail `if` whose arms are paths, such as the unit variants in `if n > 10 { Level::High } else { Level::Low }`, now reaches the return sink like one whose arms are literals. A test that pins the variant at the boundary reads the `predicate` finding as `exposed` instead of `propagation_unknown`. A test that pins only a value far from the boundary still reads `weakly_exposed` in both shapes (#15274).
