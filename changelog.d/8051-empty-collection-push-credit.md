- A Rust test that expects a collection to be empty after the owner call (`assert_eq!(p.log, vec![])`, `assert!(p.log.is_empty())`, `assert_eq!(p.log.len(), 0)`) no longer credits a changed or deleted push or insert into that collection as `exposed` when the owner can return before it (`if self.locked { return; }`, `?`, a panicking call). That test took the early exit, so the assertion cannot tell the push apart from its mutants. Without an earlier exit the assertion keeps its strength, since a test that removes what was pushed can still catch a changed argument (#8051).
