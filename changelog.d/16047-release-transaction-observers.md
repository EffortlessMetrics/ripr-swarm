- Add the decision core of the crates.io release transaction: a typed request with packages in dependency order, classification of observed registry state, and a read-only `cargo xtask release-crates-io-transaction-plan` that names the single next upload or a terminal stop. It reads no registry state and uploads nothing ([ripr#1649](https://github.com/EffortlessMetrics/ripr/issues/1649)).
- Add the read-only observer of the exact GitHub release transaction: `cargo xtask release-github-transaction-observe` reads the request's tag, releases and expected asset bytes with GET requests only and prints the inventory the plan command consumes. A failed or partial read is reported as unavailable, never as absent. It writes nothing ([ripr#1644](https://github.com/EffortlessMetrics/ripr/issues/1644)).
- The GitHub release transaction request now names the signer workflow and source ref of its provenance, and `cargo xtask release-github-transaction-observe` verifies each downloaded subject with `gh attestation verify` against the repository, that workflow and ref, and the candidate commit. A subject that cannot be verified is reported unavailable ([ripr#1644](https://github.com/EffortlessMetrics/ripr/issues/1644)).
- Add the read-only observer of the crates.io release transaction: `cargo xtask release-crates-io-transaction-observe` reads each requested package version from the registry API and the sparse index, downloads the archive of a present version and prints the inventory the plan command consumes. A version the two sources disagree on is reported unavailable, never absent. It uploads nothing and holds no credential ([ripr#1649](https://github.com/EffortlessMetrics/ripr/issues/1649)).
