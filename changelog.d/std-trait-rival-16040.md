- A Rust trait impl method that takes `&self` or `&mut self` is no longer credited as directly called by `value.name()` when another standard library trait has a method of that name at an earlier method-probing step (by value before `&self`, by value or `&self` before `&mut self`). For example, `Foo::new(5).into_iter()` on an `Iterator` runs `IntoIterator::into_iter(self)`, not a workspace `Peeky::into_iter(&self)`. The test is now related by name only. A call through the owner's trait path (`Peeky::into_iter(&foo)`) keeps its credit. So do an owner that takes `self` by value, a name no standard trait has, and the standard trait's own impl (#16040).
