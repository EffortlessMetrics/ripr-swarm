- A test that binds `let f: Fahrenheit = Celsius(100).into();` now relates to a changed `impl From<Celsius> for Fahrenheit` as a direct owner call, the same as `Fahrenheit::from(Celsius(100))`, so a whole-value assertion on `f` reads `exposed`. Before, the test was related only by file and read `weakly_exposed` with reach not established. Only a non-generic `From` impl with no `cfg`, between plain types that have no generic parameters and are not shadowed by a `fn`, `const`, `static` or `let` binding of the same name, counts. The target must be named by the `let` annotation, and the receiver must be exactly the source type (never behind `&`, and never able to `return` or `?` first). The workspace must be closed, with no `fn into` and no other `From` impl for the same pair however it is spelled. Every other spelling keeps its old reading (#15277).
- An operator, `assert_eq!`, loop, drop or `str::parse` relation no longer credits a changed impl when a `fn`, `const`, `static` or `let` binding of the type's name in the test's file shadows its constructor. `Money(1) + Money(2)` under a test-module `fn Money(..) -> Cash` read `exposed` for `impl Add for Money` although it adds two `Cash` values (#15277).
