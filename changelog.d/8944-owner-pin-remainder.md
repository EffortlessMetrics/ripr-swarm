- Owner-pin now refuses an expected value that a `matches!`-family macro scrutinises with a `ref mut` pattern (`matches!(name, Some(ref mut r) if { *r = 1; true })`) and an edition-2015 `match ::name { ref mut r => .. }` head, which the qualifier peel read as a plain read (#8944). It no longer refuses the name because of a `ref mut` in a `match` arm body (`match name { _ => { let ref mut r = other; } }`; only arm patterns and guards are scanned), a `use m::name as other` rename, or an assignment after an `if let` / `while let` with a `ref mut` pattern on another scrutinee (`if let Some(ref mut r) = a { y = name; }`). `.clone()` scrutinees and call-result borrows stay refused because a cloned `Rc`/`Arc` still aliases the value.
