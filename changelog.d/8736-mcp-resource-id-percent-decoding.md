- `ripr mcp --stdio` resource routes `ripr://gap/{canonical_id}` and `ripr://repair-card/{canonical_id}` now try the raw captured id first and, when it misses with `item_not_found`, percent-decode the segment once and retry; when the raw and decoded spellings name two distinct existing items the read fails closed with `id_ambiguous`: canonical ids embed raw workspace-relative paths (spaces, `#`, and non-ASCII are literal), so URI-emitting clients that encode those characters no longer loop on `item_not_found`, and a pathological spelling can never silently resolve the wrong item. The resource template descriptions declare this id grammar and name the equivalent tool route (a plain JSON string id) as the fallback (#8736).
