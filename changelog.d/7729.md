- Drill-in and recovery commands (`ripr check` "Next:" routes, `ripr explain`/`ripr context` navigation, JSON `detail_route`/`alternatives[].route`, first-pr regeneration commands, and the agent workflow surfaces) are now quoted for the shell family of the host ripr runs on. On Windows, arguments use double quotes with interior quotes doubled — the one form cmd.exe, PowerShell, and Git Bash all honor for spaced paths — so pasting an emitted command into the default Windows console no longer splits spaced roots on the space and passes stray quote bytes as arguments. Off Windows the bash single-quote form is unchanged. The bounded recovery parser agrees with the renderer on both hosts (literal backslash and doubled-quote semantics inside Windows double quotes), so a displayed route still recovers to its exact argv. Control/bidi characters keep the explicit `printf` escape form on both hosts. Values carrying `$` or backtick keep the single-quote form on Windows — literal in Git Bash and PowerShell, which would both expand them inside double quotes, while cmd.exe passes the quotes through and the command fails closed — and values carrying `%` paste in PowerShell or Git Bash, not cmd.exe, which expands `%VAR%` even inside quotes. A trailing backslash run is doubled before the closing double quote so a root ending in a separator round-trips through the native argv parser, Git Bash, and PowerShell instead of escaping the closing quote. The PowerShell translation understands the console form (literal backslashes, doubled interior and trailing quotes) instead of withholding on every backslash path, so redirect commands keep their guarded UTF-8 write twin on Windows. The shell disclosure, first-pr claims, and workflow manifest `command_shell` field now state the host's actual shell instead of claiming commands are bash-only on Windows (#7729).
