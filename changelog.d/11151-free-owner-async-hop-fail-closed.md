- An owner (free function or inherent method) reached only through an `async fn` hop earns `helper_owner_call` credit only for a test that drives the hop: the call is `.await`ed in code the test executes (for example a `#[tokio::test]` body), or is the sole argument of a test-local poll-to-completion helper verified from source (RIPR-SPEC-0197). Every async hop between the test and the owner must `.await` its own callee, and the lowest hop must `.await` its call into an owner that may return a future (an `async fn`, an unreadable declaration, or a plain `fn` whose return type names `Future`/`Pin` or whose body holds an `async` block or closure, so a sync owner using a closure also needs that await under an async hop); a hop-local binding or nested `fn` named like the callee refuses. A test that only constructs or drops the future, a third-party `block_on` (`futures::executor`, `tokio::runtime`) and an undeclared or unreadable declaration stay at `same_test_file`. This extends the inherent-owner fail-closed rule to free-function owners while keeping credit for directly awaited tests and sole-argument verified poll helpers (#7415, #11065, #11151). Not credited (recall only): `block_on(async { load(10).await })`, a synchronous middle hop returning `impl Future`, stored-then-awaited futures, spawn/join, and third-party executors. "Driven" has the same execution parity as synchronous call credit: dead branches, code after `return`, `cfg(any())` items and zero-iteration loops are not excluded. A return type hidden behind a type alias is not seen, and the hop shadow guard is name-based and fail closed: it refuses local bindings, nested `fn`s, any `use` that binds the callee's name by final segment or `as` rename in the hop's file (so `use ext::inner;`, `use other::different as inner;` and the callee's own `use crate::inner;` all refuse by design, while a rename or import of another name does not), and ANY glob `use` in the hop's file wherever the callee is defined. Recall cost: a hop file with a glob import, including a `use crate::*;` prelude, is not credited; only a glob inside a `#[cfg(test)]` module that does not contain the hop (the in-file `mod tests { use super::*; }`) is exempt. Not detected: imports in other files, a qualified path to an external item of the same name, name binders other than `use` (a const, static, tuple-struct constructor, `extern crate .. as inner`, macro-generated items) and a `use` inside a `macro_rules!` body. Hop calls are matched by name (a method's receiver type is not resolved) and every same-named call in the hop must be driven; an unrelated same-named workspace method is refused upstream because the chain only follows a workspace-unique callee name (pinned as that, not as a scan property). The compact helper path (`inherent_helper_path_reaches_owner`) still refuses every async helper, a fail-closed divergence.
