- The `ripr explain` and `ripr context` selector-miss message no longer dead-ends when the id came from uncommitted edits. When the run was not `--worktree`, the selector is id- or location-shaped, and the selected root actually has staged or unstaged tracked changes, the miss now appends one clause: uncommitted edits are not analyzed without `--worktree`, with the working retry bound to the run's own scope (`ripr explain --root <repo> --base <rev> --worktree <id>` / the context counterpart), not a bare prefix that would analyze the caller's directory and the worktree listing (`ripr check --worktree --json`). Previously the printed advice — a committed-history listing — demonstrably listed zero findings in exactly that state. Clean repositories keep the unchanged message (#7328).
