- `ripr check` refusals for an exhausted wall-clock budget (`analysis_timeout`) now retain availability-aware input context instead of only generic recovery prose (#10796). The refusal envelope renders at generation `0.3` with an `input_context` key: the requested root/source/base/diff/scope echo (never confusing analysis mode with source mode), each resolved base/commit/merge-base and scoped input-count fact marked available or named unavailable with its reason (`not_published_before_deadline` vs `not_computed_for_source`), and one shell-safe literal bounded retry (`retry_with_larger_budget`, 2x the expired budget) that states what a retry re-reads and that it is not pinned to the timed-out run's snapshot. Facts come only from producers that completed before the deadline — no new discovery runs after it — and human-format refusals carry the same recovery on stderr. Exit 2, the typed identity, empty findings, the zeroed analysis summary, and `downstream_consumable: false` are unchanged, and every non-timeout refusal keeps its existing bytes. See RIPR-SPEC-0241 amendment #10796.
