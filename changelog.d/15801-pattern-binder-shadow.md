- An operator, `assert_eq!`, loop, drop or `str::parse` relation no longer credits a changed impl when the test's file binds the type's name as a value: a `fn`, `const`, `static` or `let` of that name, or any pattern that binds it. A braced struct lives only in the type namespace, so a closure or function parameter, a `for`, `match`, `if let` or `while let` binding, or a `let` pattern such as `let (a, Celsius)` or `let ref Celsius` can carry its name, and `Celsius(1)` then calls that value. `let (_, Celsius) = (1, Kelvin as fn(i32) -> Kelvin); assert_eq!(Celsius(1) + Celsius(2), Celsius(3));` read `exposed` for `impl Add for Celsius` although it adds two `Kelvin` values. Before, `Money(1) + Money(2)` beside a test-module `fn Money(..) -> Cash` read `exposed` too (#15801).
