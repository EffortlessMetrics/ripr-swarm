- A Perl change to an ordering comparison (`<`, `>`, `<=`, `>=`, `lt`, `gt`, `le`, `ge`, `<=>`, `cmp`) no longer reads `exposed` just because an exact assertion names the same expression: that assertion may use inputs far from the threshold. It now reads `exposed` only when the assertion's owner call passes the threshold literal, and otherwise `static_unknown` with no repair gap and a next step that says what settles it. Equality tests and comparison-free sinks keep their alignment. A test that reaches the boundary only through non-literal inputs reads `limited` until the fact producer emits a row-owned predicate-input fact (#8979). The check is a bounded lexical read of the changed expression and the assertion text, not a Perl parser: it does not know which call argument position carries the literal, it withholds when the assertion text holds a regex, heredoc, backtick or quote-like construct or calls the owner twice, and it can over-withhold or, for constructs it does not recognize, misread.
