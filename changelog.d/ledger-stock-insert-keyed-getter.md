- A field-map insert (`self.stock.insert(sku.to_string(), qty)`) is now credited when a test reads the inserted entry back through a keyed getter whose body looks its argument up in that field (`fn count(&self, sku: &str) -> u32 { self.stock.get(sku).copied().unwrap_or(0) }`), and the test passes the same key to the owner and the getter. A read of another key, a getter that looks the key up in another field or computes from the entry, and a call to an owner that returns a value without consuming its result through `.unwrap()`, `.expect(..)` or `?` (`unwrap_err()`, `is_err()`, `let r = inv.ship(..)`) still leave the finding weakly exposed. So do a test binding not built empty by a verified constructor or declared more than once, an earlier call on the binding that may already store the expected value, a write on the assertion's own line, a `return` anywhere before the assertion, a type name declared in two modules, and an owner that touches the map again after the insert (RIPR-SPEC-0228 examples 16-20) (#7960).
