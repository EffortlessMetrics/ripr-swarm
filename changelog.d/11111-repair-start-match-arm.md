- `ripr check` and `ripr repair` now offer a repair start for a changed match arm when one related test calls the changed function directly, passes the arm's own literal directly as the matched argument (`rate("silver")`) in its only call of that function, and checks that call's result only loosely. The function body must be a single `match` on that argument, and every earlier arm must be a plain literal. They use the same conditions as a changed return value, and both commands still decline when the literal and the assertion sit in different tests or different calls, the call sits inside a branch or closure, the literal comes through a local variable, a method is called as `Type::method(value, ..)`, an earlier arm already names the literal, the literal goes to another argument, the matched value is derived, the arm is nested or follows a guard, the test ignores the result, or the call goes to a type declared more than once (#11111).
