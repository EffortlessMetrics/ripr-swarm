- Python module-level edits are credited when a test's assertion statically depends on the edited value. A `NAME = <literal>` constant edit is `exposed` when an `assert` in a test that imports the module holds under the old literal and fails under the new one, read either directly (`assert LIMIT == 10`) or through a module function the test calls with literal arguments (`assert over_limit(11)` for `return n > LIMIT`), under a bounded evaluator; a function defined under a decided `if sys.version_info >= (3, 0):` condition is now a function owner an exact-value assertion can credit. Anything the evaluator cannot decide (an unmodeled name, call or operator, a rebound, patched, `global`, star-imported or reassigned constant, an assertion that may not run, a diff with other changed lines in the file) keeps the `missing_import_graph` abstention, and a value no assertion distinguishes is not graded as a gap (#9423).
