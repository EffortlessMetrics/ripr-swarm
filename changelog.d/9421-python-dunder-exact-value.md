- Python dunder owners now credit a test that builds the instance and reads the dunder through an operator or `with` expression against an exact value (`assert Money(5) + Money(7) == Money(12)`, `(a + b).cents == 12`, `with Recorder() as rec: ...` then `assert rec.events == [...]`), but only where the receiver's class and the operator are statically certain: the receiver is built in the test from the owner's own class, the operator runs exactly that dunder (left operand, literal or same-class right operand, `!=` only when the class defines no `__ne__`), and a `with` target is the manager only when `__enter__` returns `self`. Anything else keeps the `dynamic_dispatch` abstention, and an equality dunder no assertion pins abstains instead of reading as a gap (#9421).
