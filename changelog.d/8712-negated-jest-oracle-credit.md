- TypeScript negated Jest/Vitest assertions are no longer dropped from the assertion inventory: `expect(x).not.toBe(y)` and the other `.not` forms now earn capped credit exactly as the chai `.not` and AVA `t.not` negations already do — exact and relational matchers read `relational_check` / weak, the smoke list stays smoke, `toThrow*` reads `broad_error` / weak with the exact-payload override disabled, the mock list reads `mock_expectation` / weak, and unrecognised matchers (including snapshots) read `unknown` / unknown (RIPR-SPEC-0243 rule 2). A negated matcher operand is not an expected value: it carries no `expected_value_or_variant` and no `typescript_oracle_expected` line, and a test whose only assertion is negated no longer reports `typescript_oracle_helper_gated` (#8712).
