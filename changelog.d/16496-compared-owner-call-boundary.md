- A TypeScript or JavaScript test that passes the changed boundary input to a free function, but asserts something other than the call's result, now reads at most `weakly_exposed`. Examples are a comparison (`expect(discount(100) > 0).toBe(true)`), arithmetic, a negation or a template. These read `exposed` before, even when the assertion passes on both sides of the boundary. A call written only inside a comment no longer supplies a boundary input either. The whole call, a one-hop local, parentheses, `await`, `Promise.resolve` and a namespace member call still count, the same rule renamed imports and class methods already follow (#16496).
