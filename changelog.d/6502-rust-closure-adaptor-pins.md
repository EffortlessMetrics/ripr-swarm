- A Rust owner whose whole body is one closure in a `filter`, `map`, `any` or `all` adaptor over a slice parameter (`xs.iter().filter(|&&x| x > 0).count()`) no longer reads as a gap when its tests pin it: the closure binding takes the elements of a literal sequence the tests pass (`&[-1, 0, 3, 7]`, a constant-row table, or a check helper's calls), so a boundary element such as `0` is an observed input, and the owner-return pin holds when the pinned call passes a non-empty literal sequence. Only consumers that keep every closure value are read (`filter` + `count`, `filter`/`map` + `collect` into a `Vec`, `map` + `sum` over arithmetic, `any`, `all`); `map` + `count`, `filter` + `sum` and a `collect` into a set keep the earlier reading. An empty slice, a sequence without the boundary element (or one a short-circuiting `any`/`all` never reaches), and any argument ripr cannot read still leave the gap or the unknown, as RIPR-SPEC-0260 specifies (#6502).
