- `ripr mcp --stdio` no longer goes silent for the length of a `ripr_refresh`: while one runs, `ripr_workspace_status` (reporting `attempt_state: "in_flight"`), `ping` and the catalog listings are answered, and a `ripr_refresh` sent again is refused `analysis_in_flight` instead of queueing a second full analysis. A snapshot or repair read written during a refresh still waits for it and reads the snapshot it commits on success; requests written behind such a held read wait with it. The `ripr_refresh` description now says a refresh can take minutes and that after a client timeout the agent should poll status instead of sending it again (#15983).
