- `ripr repair` and the `ripr check` repair line now give a specific answer for a changed field write in a method (`self.count += 1`, or a builder's `self.timeout = t * 2; self`) instead of "your changed lines touch no code ripr can start a repair on". If no test reads the field, both name the missing check of that field. If a test checks it exactly, both say it is already checked. If a test mentions the field but ripr cannot judge the read, both say so, and neither claims the field is unchecked. `ripr check` no longer tells you to match an `Err` wrapper for such a change; it says to assert the changed field on the value you called the method on. No field write starts an automatic repair (#11398).
