- `ripr repair` and the `ripr check` repair line now give a specific answer for a changed field write in a method (`self.count += 1`, or a builder's `self.timeout = t * 2; self`) instead of "your changed lines touch no code ripr can start a repair on". If no test reads the field, both name the missing check of that field. If a test checks it exactly, both say it is already checked. If an assertion names the field but ripr cannot confirm it reads the written value (a builder chain, a weak comparison, a by-value builder on a `Copy` type), both say ripr could not judge it, and neither claims the field is unchecked or already checked. `ripr check` no longer tells you to match an `Err` wrapper for such a change; it says to assert the changed field on the value you called the method on, and that ripr cannot yet confirm such a check for a builder that takes `self` by value. No field write starts an automatic repair (#11398).
