- The after-phase edit cage no longer counts a git-invisible line-ending flip as an agent edit. Each captured worktree file now also records the digest of its CRLF-normalized bytes, and a path whose exact digests differ only by line-ending style (for example a `core.autocrlf` checkout rewrite or `git stash pop` between phases, where `git status` stays clean) stays out of the changed-path decision, while any real content change still refuses as before. The cage-violation recovery narration now names the autocrlf line-ending flip as a possible cause next to "undo the refused changes" (#7377).
