- The default `ripr check --format json` findings-array byte budget no longer cuts in file order, which hid the last files' findings first. When the budget engages it keeps the highest-priority findings (candidate-current before base-side or unresolved ones, then `reachable_unrevealed`, `weakly_exposed`, `no_static_path`, the unknown classes, `exposed` last, then having a recommended next step, with the sort order as final tiebreak) and still emits them in the unchanged sort order. The `limited_findings_bound` message now names what was dropped (counts per class and per file) and `RIPR_CHECK_FINDINGS_BYTES=0` as the way to see all of it. A budget that does not engage is byte-identical to before. Priority is by currentness, class and a recommended next step only: within one of each the sort order still decides, so a tie can still hide a late finding (#10093).
